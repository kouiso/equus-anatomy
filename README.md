# EQUUS — 馬体解剖

馬の解剖を層ごとに学ぶアプリ。左側望・右側望・正面・後面 × 皮膚・筋肉・骨格・内臓の図に、
タップできる部位を重ねる。

## このリポジトリが解こうとしとる問題

前身（AI 支援で作った版）は、部位のマーカーが馬体からズレとった。
配信中のコードと画像を実測して原因を確定させた結果はこうやった。

- 描画（SVG の viewBox 1本）は**正しかった**。画像・領域・マーカーが同じ座標系に乗っとる
- 向きごとのデータ分離も**正しかった**
- 層ごとの絵の姿勢も**揃っとった**（左側望4層のランドマーク差は最大 8px）
- **座標の数値そのものが、画像を測らずに書かれとった**

実測すると、前身の座標 26 件のうち **11 件（42%）が馬体やのうて背景に落ちとった**
（`pnpm tsx scripts/migrate/legacy-audit.ts` で再現できる）。

なので、このリポジトリの設計はこの一点に集約される。

> **座標は人が実測したものしか入れん。測られてへん座標は CI で機械的に弾く。**

## 座標ゲート

`pnpm validate:coords` が次を検査して、外れとったら落ちる。

| 検査 | 内容 |
|---|---|
| 馬体の上か | JPEG から抽出した実測シルエットに対して、頂点と重心が馬体に乗っとるか |
| 画像の同一性 | 画像の SHA-256 が記録と一致するか（差し替わったら座標は無効） |
| 座標系の一致 | 画像の実寸と座標ファイルの `size` が一致するか |
| 解説との整合 | `id` が存在するか、`layer` と `depth` が解説と食い違うてへんか、その向きに出す部位か |
| 形として成立するか | 頂点3つ以上か、面積が潰れてへんか、画像の外に出てへんか |

シルエット抽出は輝度のしきい値やのうて、**背景色から縁のフラッドフィル**でやっとる。
単純なしきい値やと暗い鹿毛（`skin_left.jpg`）が背景に落ちるため。

ゲートが捕まえられるのは「背景に落ちとる座標」まで。
**馬体の上には乗っとるが別の部位を指しとる誤りは、人が見るしかない。** そこは自動化してへん。

## 座標の作り方

1. **VIA 2**（単一 HTML をローカルで開く。アカウント不要）か **CVAT + SAM** で輪郭をなぞる
2. `pnpm import:annotations <入力.json> <left|front|rear>` で取り込む（VIA / VGG / COCO 対応）
3. `/calibrate` で微調整し、本番と同じ描画で確認する
4. `pnpm validate:coords` を通す

`/calibrate` で置いた下書きは `localStorage` に入り、解剖画面に重ねて即プレビューできる。
出した JSON が正しいかを本番の絵で確かめる経路が要るのでこうしとる。

## React Native への移植

最終的に RN にする前提で、DOM に依存する部分と依存せん部分を最初から分けとる。

```
src/core/    ← 純 TS。DOM も React も import せん（ESLint で機械的に禁止）
  geometry / hit-test / zoom / types / data
src/web/     ← ここだけ差し替える
  AnatomySvg（<svg viewBox>）/ useGestures（Pointer Events）
```

当たり判定はブラウザの `pointer-events` に任せず `core/hit-test.ts` でやっとる。
`react-native-skia` に載せ替えても同じ判定・同じテストが効くようにするため。
ズームの状態も `core/zoom.ts` が持ち、renderer は viewBox（RN なら matrix）へ写すだけ。

## 描画で外したらアカン点

| # | やっとること | 理由 |
|---|---|---|
| 1 | マーカーに `scale(k)`。`k` はズーム倍率と**コンテナ実寸**の両方を含む | `vector-effect="non-scaling-stroke"` は線の太さにしか効かん。`non-scaling-size` は未実装。前身は固定値やったのでスマホで点が極小になっとった |
| 2 | 不可視の当たり円 `r=22` CSS px | WCAG 2.5.8 の 24×24 |
| 3 | 領域は `fill="transparent"` | `fill="none"` は内側が当たらん |
| 4 | ズームは viewBox の書き換え。HTML への CSS transform は使わん | Safari で `getScreenCTM()` が CSS scale を拾わん報告がある |
| 5 | `touch-action: none` を最初から | 後から付けても効かん |
| 6 | 点は先に全部描いてからラベルを重ねる | 隣のラベルが点を覆うと押せんようになる |
| 7 | viewBox は向きの切り替えと同じレンダーで決める | `useEffect` に置くと1フレームだけ前の向きの枠で描く |

## コマンド

```bash
pnpm dev                # 開発サーバー
pnpm verify             # 型・lint・単体・座標ゲート・ビルド・e2e を通しで
pnpm measure:silhouette # 画像から馬体マスクを作り直す（画像を差し替えた時）
pnpm validate:coords    # 座標ゲート
pnpm import:annotations # VIA / COCO → regions JSON
pnpm shots              # スクリーンショットを撮る
```
