# EQUUS — 馬体解剖

馬の解剖を層ごとに学ぶアプリ。左側望・右側望・正面・後面 × 皮膚・筋肉・骨格・内臓の図に、
タップできる部位を重ねる。

**Expo（React Native）で作っとる。** Web は `expo export --platform web` で同じコードから出す。
「Web で作って後で RN に移す」はやめた。RN でできん物を最初から書けんようにするため。
座標計算・当たり判定・ズームは `src/core/`（純 TS）が持ち、画面は `src/ui/` と `src/app/` が持つ。

## このリポジトリが解こうとしとる問題

前身（AI 支援で作った版）は、部位のマーカーが馬体からズレとった。
配信中のコードと画像を実測して原因を確定させた結果はこうやった。

- 描画（SVG の viewBox 1本）は**正しかった**。画像・領域・マーカーが同じ座標系に乗っとる
- 向きごとのデータ分離も**正しかった**
- 層ごとの絵の姿勢も**揃っとった**（左側望4層のランドマーク差は最大 8px）
- **座標の数値そのものが、画像を測らずに書かれとった**

実測すると、前身の座標 26 件のうち **11 件（42%）が馬体やのうて背景に落ちとった**
（`pnpm tsx scripts/migrate/legacy-audit.ts` で再現できる）。

なので、このリポジトリの設計はこの一点に集約される。

> **測った座標と、AI が引いた下書きを混ぜん。混ぜんことを機械で担保する。**

座標には出どころ（`source`）を必ず持たせる。

| source | 意味 | 今の中身 |
|---|---|---|
| `measured` | 実測。人が図の上で採った値か、実測マスクから切り出した輪郭 | 大まかな場所 6 件 |
| `draft` | AI が図を見て引いた下書き。人の確認待ち | 表層筋 13 件（左側望） |

下書きは画面上で**破線**で描き、`pnpm validate:coords` が残数を毎回報告する。
「いつの間にか確認済みになっとった」が起きんようにする。

## 座標ゲート

`pnpm validate:coords` が次を検査して、外れとったら落ちる。

| 検査 | 内容 |
|---|---|
| 馬体の上か | JPEG から抽出した実測シルエットに対して、頂点と重心が馬体に乗っとるか |
| 画像の同一性 | 画像の SHA-256 が記録と一致するか（差し替わったら座標は無効） |
| 座標系の一致 | 画像の実寸と座標ファイルの `size` が一致するか |
| 解説との整合 | `id` が存在するか、`layer` と `depth` が解説と食い違うてへんか、その向きに出す部位か |
| 形として成立するか | 頂点3つ以上か、面積が潰れてへんか、画像の外に出てへんか |

シルエット抽出は輝度のしきい値やのうて、**背景色から縁のフラッドフィル**でやっとる。
単純なしきい値やと暗い鹿毛（`skin_left.jpg`）が背景に落ちるため。

ゲートが捕まえられるのは「背景に落ちとる座標」まで。
**馬体の上には乗っとるが別の部位を指しとる誤りは、人が見るしかない。** そこは自動化してへん。

| 正面 | 22 / 23 | 4 | 1 |
| 後面 | 10 / 10 | 2 | 0 |

左側望の内訳。

| 層 | 件数 | 出どころ |
|---|---|---|
| 皮膚 | 11 | うち 7 件が実測（耳介・頭部・頸・尾・管・蹄・飛節）。残り4件は区分の線引きが要るので下書き |

78 件のうち **66 件は下書き**。破線で描いて、ゲートも件数を出す。

**置けんかった 6 件と、その理由。**

| 部位 | 理由 |
|---|---|
| 棘上筋・棘下筋・鎖骨下筋・腸腰筋 | 深層筋の図が元アプリにも存在せん。絵が無いものは置けん |
| 盲腸 | 左側望では他の腸管に隠れて輪郭が取れん |
| 膀胱 | 骨盤腔の中で、この図には描かれとらん |

推測で埋めると「間違った位置を教える」ことになるので空にしてある。画面には「未配置 N 件」と数が出る。

### どうやって座標を採ったか

**大まかな場所（実測）** — JPEG から抽出した馬体マスクを切り取って輪郭を取る
（`pnpm tsx scripts/derive-areas.ts`）。人が決めるんは切り取り線だけで、輪郭は実測値そのもの。
切り取り線の根拠も実測（耳の突起は x=228 で上端 y=52、腹線は y=660、y=860 で塊が5個に割れる）。

**皮膚の一部（実測）** — 体表のかたちそのものなのでシルエットから決まる。
管は「幅 40px の一定区間」、蹄は「最下部で幅が広がる区間」、飛節は「後縁が張り出す区間」。

**筋・骨・内臓（下書き）** — 目盛りを焼いた拡大図で位置を読み、重ねて描いて目で直す、を繰り返した。

```
pnpm tsx scripts/crop.ts muscle_left.jpg 400 150 560 560   # 目盛り付きで切り出す
pnpm tsx scripts/derive-parts-left.ts                      # 置いて shots/debug-parts.jpg に焼く
pnpm tsx scripts/audit-parts.ts left                       # 1件ずつ拡大して確かめる
```

**位置は解剖学的に正しい所に乗っとるが、境界は概算。** 元選手の目での確認が要る。

### 「概算」がどれくらいかを数字で出す

「概算です」で終わらせると、どれくらい概算なのか誰にも分からん。
同じ層の部位どうしの重なり率を測って出す。

```
pnpm report:overlap left
```

今の数字（重なり 15% 以上の組だけ）。

| 組 | 重なり | 判定 |
|---|---|---|
| 耳介 × 頭部 | 96% | 耳は頭の一部。小さい耳がタップで勝つので問題なし |
| 肩甲骨 × 肋骨 | 71% | 肩甲骨は肋骨の上にある。投影上ほんまに重なる |
| 肋骨 × 胸骨 | 39% | 胸骨は胸郭の底。重なって当然 |
| 仙骨 × 骨盤 | 27% | 側面から見ると重なる |
| 頸 × 胸前 | 20% | 隣り合う区分 |
| 三角筋 × 上腕三頭筋 | 15% | 隣り合う筋 |

**大きい部位の重心が小さい部位の中に入っとる組はゼロ。**
これがあると「その部位を叩いたのに別の部位が出る」ことになる。テストで固定しとる。
最初に測った時は僧帽筋の重心が脾状筋の中に入っとって、実際に壊れとった。

### 絵そのものを疑うこと

内臓の図は AI 生成で、心臓と肺の位置関係が解剖学的に怪しい。
**絵が間違うとる所へ正しくラベルを置いても、間違いを教えることになる。**
座標を直す前に絵を疑う。権威ある図版（Ellenberger 等、パブリックドメイン）への差し替えを検討する段階。

## 座標の作り方

1. **VIA 2**（単一 HTML をローカルで開く。アカウント不要）か **CVAT + SAM** で輪郭をなぞる
2. `pnpm import:annotations <入力.json> <left|front|rear>` で取り込む（VIA / VGG / COCO 対応）
3. `pnpm validate:coords` を通す
4. アプリで見て確かめる（`pnpm web`）

測る道具は `tools/calibrator/` の単一 HTML に一本化した（アプリ内の `/calibrate` は無い。
Web にしか無い物をアプリに持たせんため）。clone せんでもスマホのブラウザだけで測れる。

```
pnpm build:calibrator            # 画像12枚と解説を埋め込んだ 1 ファイル（0.65MB）
```

## 構成

```
src/core/    ← 純 TS。DOM も React も RN も import せん（ESLint で機械的に禁止）
  geometry / hit-test / zoom / screen-to-image / label-layout / types / data
src/ui/      ← react-native-svg のキャンバス、チップ、部位シート、保存ストア、テーマ
src/app/     ← expo-router の画面。(tabs)/ に 図鑑・解剖・保存、catalog/[id] は図鑑タブの中
assets/      ← 画像 12 枚。RN は require で同梱するので public には置けん
scripts/     ← シルエット抽出・座標ゲート・切り抜き・派生（node、画面には依存せん）
tools/       ← 単一 HTML のキャリブレータ
```

当たり判定はブラウザの `pointer-events` に任せず `core/hit-test.ts` でやる。タップ位置は
`core/screen-to-image.ts` で画像 px に直す（SVG の `getScreenCTM()` は RN に無い）。
ズームの状態も `core/zoom.ts` が持ち、renderer は viewBox へ写すだけ。

Web にしか無い物（`lang`・`title`・`theme-color`・`color-scheme`）は `src/app/+html.tsx` だけに置く。
マウスホイールのズームは付けてへん。RN に無い物はこのアプリに書かん。

## 描画で外したらアカン点

| # | やっとること | 理由 |
|---|---|---|
| 1 | マーカーに `scale(k)`。`k` はズーム倍率と**コンテナ実寸**の両方を含む | `vector-effect="non-scaling-stroke"` は線の太さにしか効かん。`non-scaling-size` は未実装。前身は固定値やったのでスマホで点が極小になっとった |
| 2 | 不可視の当たり円 `r=22` CSS px | WCAG 2.5.8 の 24×24 |
| 3 | 領域は `fill="transparent"` | `fill="none"` は内側が当たらん |
| 4 | ズームは viewBox の書き換え。HTML への CSS transform は使わん | Safari で `getScreenCTM()` が CSS scale を拾わん報告がある |
| 5 | `touch-action: none` を最初から | 後から付けても効かん |
| 6 | 点は先に全部描いてからラベルを重ねる | 隣のラベルが点を覆うと押せんようになる |
| 6b | ラベルは画面 px で当たりを見て空いとる向きへ逃がす（`core/label-layout.ts`） | 隣り合う筋は重心も近く、肩まわりで5枚が重なって読めんかった |
| 6c | 場所を選んだ時は「輪郭」やのうて「そこに出る部位の範囲」へ寄せる | 前肢は縦に長く、輪郭に合わせると画像全体に戻って寄る意味がなくなる |
| 7 | viewBox は向きの切り替えと同じレンダーで決める | `useEffect` に置くと1フレームだけ前の向きの枠で描く |
| 8 | タップは**まず点**、外れたら多角形（`core/hit-test.ts` の `hitTestMarkers`） | 多角形だけやと「見えとる点を押しても別のものが選ばれる」形が作れてしまう。下の節 |

### 見えとる点は必ず押せる

多角形だけで当たり判定すると、こうなる。

- 正面の「前肢」は胸から蹄まで枠が伸びるので、重心が「体幹」の枠の**内側**に落ちる。
  小さい方が勝つ規則なので、前肢の点を押すと体幹が選ばれる。前肢の筋には一生たどり着けん。
- 左側望の「尾」は L 字の輪郭なので、重心が**自分の外**へ出る。点を押しても何も起きん。

実際に4つの向きで 18 個の点を調べたら **3 個が押せんかった**。形の問題なので、
座標を1つずつ直しても同じ形がまた生える。だから当たり判定の順番を変えた。

1. 画面に出とる点（半径 22 CSS px）を先に見る。近い方が勝つ
2. 外れたら今までどおり多角形

これで「見えとるのに押せん点」は原理的に作れんくなる。加えて、点が変な所に出る
（尾の点が尾の外に浮く等）のは見た目の問題として残るので、`labelAt` で位置を指定した。

固定しとるテストは2枚。`src/core/data/marker-reachable.test.ts` が全4向き・全層で
「点を押したら自分が返る」ことを検査し、e2e が実際のブラウザで
「押した場所の部位が出る」ことを検査する。当たり判定を戻すと e2e が落ちるのを確認済み。

## コマンド

```bash
pnpm start              # Expo（QR を Expo Go で読む）
pnpm web                # ブラウザで開発
pnpm build              # expo export --platform web → dist/
pnpm preview            # dist/ を 4173 で配信
pnpm verify             # 型・lint・単体・座標ゲート・ビルド・e2e を通しで
pnpm measure:silhouette # 画像から馬体マスクを作り直す（画像を差し替えた時）
pnpm validate:coords    # 座標ゲート
pnpm import:annotations # VIA / COCO → regions JSON
pnpm refresh:meta       # 各向きの寸法・ハッシュ・枠を実測から書き直す
pnpm report:overlap     # 同じ層の部位どうしの重なり率を出す
pnpm shots              # スクリーンショットを撮る
```

Node は mise（`mise.toml`）で 22 を、パッケージは pnpm を使う。Metro が symlink を辿れんので
`.npmrc` で `node-linker=hoisted` にしとる。

### 正面・後面の画像を切り抜いた理由

元の 1728×1152 は左右の余白が広く、**馬が画像幅の 22〜26% しか占めてへんかった**。
そのまま出すとスマホで馬が親指ほどにしかならん。`scripts/crop-images.ts` で切り抜いて、
正面 520×1136（幅の 69%）、後面 560×1144（幅の 79%）にした。

切り抜きの箱はシルエットの外接矩形に余白を足した実測値で、ROI も同じ量だけずらしとる。
`pnpm refresh:meta` が寸法・ハッシュ・枠を実測から書き直す。
枠が画像幅の6割を切ったら単体テストが落ちる。
