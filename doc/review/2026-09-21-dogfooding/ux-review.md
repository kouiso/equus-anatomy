# UX レビュー — ペルソナ・ユーザーストーリー・OOUI 化提案

*2026-09-21 | ユーザー指定ペルソナ2種に基づく評価*

## ペルソナ

- **P1「積読の獣医志望」**: 解剖を学びたいが教科書が難しくて停滞中。最初の数分で「分からない」が来ると離脱する。目標: 馬を見て部位名が言える、怪我の場所が分かる
- **P2「オリンピック級実務家」**: 解剖用語は半分知っている。馬の世話・運動・健康管理の場面で「あそこって何だっけ」を即引きたい。検索と一発表示が価値

## 現行UIの構造(実測)

| 画面 | 要素 |
|---|---|
| 解剖 | 図 + ズーム3ボタン + 下部パネル(選択状態 / 大まかな場所 / 未配置N件) + 「場所・部位一覧」「表示条件」ボタン |
| 表示条件モーダル | 向き4チップ + 層4チップ + 深さ2チップ + 閉じる + 「この条件で表示」= 計12操作対象 |
| 図鑑 | 検索 + 層4 + 場所~9 + 向き4 のチップ3行 + 52行リスト |
| 詳細 | 保存/覚えた/閉じる 3ピル + 長文4ブロック + 図鑑リンク |

## ユーザーの指摘と実測の照合

**「選ぶボタン/項目が多くて操作がムズイ」— 実測で裏付け:**

- 部位の解説を読むまで: ①解剖タブ ②大まかな場所タップ ③部位マーカータップ ④「詳しく読む」 ⑤モーダルを読む ⑥「閉じる」= **6操作・2遷移**
- 表示条件の変更: 開く→向き→層→(深さ)→「この条件で表示」= **最低4操作+モーダル1遷移**。しかも選択しても即反映されず「この条件で表示」を押すまで何も起きない
- 図鑑の絞り込みチップ3行(層/場所/向き)は P1 には「層って何?」状態。分類軸が解剖学の内部構造(layer)をそのままUIに露出している = タスクベースUI

## OOUI 化の方向(実装なし・提案のみ)

現行は「機能を選ぶ→対象が出る」のタスクベース。OOUI=「対象(馬・部位)を直接触って、属性を後から変える」。

| # | 提案 | 削減する操作 | ペルソナ効果 |
|---|---|---|---|
| U-1 | **層の切替を「皮をめくる」メタファに**。解剖図を左右スワイプ or 画面端の層スライダーで即時切替。「表示条件」モーダル自体を廃止 | 4操作→1操作。モーダル消滅 | P1: 「めくる」は物理的に直感的。P2: 層を高速往復できる |
| U-2 | **部位タップ→その場に展開するボトムシート**(モーダル遷移なし)。現行の下部パネルをそのまま膨らませる。「詳しく読む」はシート内スクロールに | 6操作→2操作 | 両者: 対象から目を離さない = OOUI の本質 |
| U-3 | **向きの切替は馬の絵を水平フリップ/回転ジェスチャ**(右側望は馬を引っ張って向きを変える感覚)。または画面上部の小さな向きピッカー | モーダル内選択を消す | P1: 「向き」という抽象概念が絵の操作になる |
| U-4 | **「大まかな場所を選ぶ」段階を省略可能に**。ズーム無しでも部位がタップできる精度があれば、場所選択は「絞り込み」として残し、初回は部位直タップも受け付ける | 1操作削減 | P2: 知っている人は直でいきたい |
| U-5 | **検索をグローバルに**(解剖画面にも)。P2 が「中手骨」で即引く導線。現行は図鑑タブ経由の2遷移 | 2遷移→0 | P2: 実務参照の速度 |
| U-6 | 保存/覚えたを部位シートからも常時(現状あり)・undo は現行のまま維持 | — | — |

**最も本質的な変更は U-1 + U-2**(画面遷移と選択肢の爆発を同時に消す)。理由: このアプリの中心オブジェクトは「馬の絵」と「部位」。対象への操作がモーダルを経由するたびに没入が切れる。層めくり+その場シートで「馬を触って学ぶ」物体性が出る。

## ユーザーファースト観点の再編案

タスクベース(図鑑/解剖/保存)から、利用場面ベースへ:

- **「見て覚える」**(P1): 解剖画面がホーム。層めくり+タップ学習が主役
- **「引く」**(P2): 検索が最上級。「昨日蹴られた場所は?」みたいな現場起点
- **「覚えたか試す」**: ラベル非表示モード(現行のquiz廃止の代替。ラベル消すだけで自習になる)

現行タブ構成は概ね良いが、「図鑑」と「解剖」は分けなくてもいい可能性がある — 図鑑=部位の一覧というより「部位から絵へ飛ぶ索引」。OOUI 的には絵が主、一覧は索引に格下げが自然。
