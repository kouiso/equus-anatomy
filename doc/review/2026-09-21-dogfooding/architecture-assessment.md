# 実装方式の本質性評価 — 「画像は外部ツール(VIA等)で編集すべきでは？」への回答

*2026-09-21 | dogfooding セッションの設計評価パート*

## 質問の整理

「今の実装は本質的な実装方法か。VIA などのツールで画像を編集する方向にしないでいいのか」

これは2つの別問題を含む:

1. **注釈(部位の位置)を誰が作るか** — アプリ内エディタ vs 外部ツール
2. **注釈をどう表現・配信するか** — 絵に焼き付け vs データとして分離

## 結論(先に)

**現行の「測定は外部ツール / データは JSON に分離 / 描画はアプリ内で SVG オーバーレイ」は、現時点の資産形態(ラスタ JPEG)に対して本質的な実装。** 変えるべきはランタイムではなく、**資産の作られ方**。絵そのものをレイヤー付きベクターで調達できれば、測定という工程そのものが消える。

「一番本質的な案」= **部位の輪郭を絵と同じデータとして生ませる(ベクター原画)**。詳細は末尾。

## 各案の評価

| 案 | 内容 | 評価 |
|---|---|---|
| A. 現行 | JPEG + JSON座標 + SVGオーバーレイ + 純TSコア | ◎ 現資産形態では本質的 |
| B. 絵に焼き付け | VIA/Photoshop でラベル・境界をピクセルに描き込む | ✗ 反対。下記参照 |
| C. VIA 等をオーサリングに使う | 測定を外部ツールで行い import | ◎ **既にそう**。`pnpm import:annotations` は VIA/VGG/COCO を受理 |
| D. ベクター原画 | SVG/レイヤーPSDで絵を作り、パス=部位として export | ◎ 根本解決(推奨の着地点) |
| E. 既存ビューワライブラリ | OpenSeadragon/Annotorious/Leaflet | △ Webのみ、RN非対応。今の hit-test コアは200行級の純TSで検証済み、乗り換え利益なし |
| F. 3D 解剖モデル | BioDigital/Zygote 的な3D | △ 「部位=メッシュ」で座標問題は消えるが、資産制作費が桁違い。現段階のボトルネック(絵の正しさ)を解かない |
| G. 既存アプリのライセンス/内製放棄 | 市販解剖アプリを使う | ✗ 自社教材としての差別化・改版自由度を失う |

### B(焼き付け)が反対な理由

絵にピクセルとして焼くと、その瞬間に以下を失う:

- タップ判定(領域データが消える)
- 層の切替・表示条件
- 和名/英名/学名の切替余地と文字修正の容易さ
- ズーム時のラベル再配置(現行は `layoutLabels` で衝突回避している)
- **検証可能性** — 焼かれたピクセルは `validate:coords` 相当の機械検査が不可能。差分もレビュー不能
- 多言語化(将来 EN UI)の道

つまり焼き付けは「データを消して絵にする」= 本質の逆方向。

### C(オーサリング外部化)は既に達成済み

README / scripts 確認済み: VIA, VGG, COCO の3形式を import 可能で、社内 calibrator(`tools/calibrator`)と vendored VIA(`tools/via`)もある。VIA は「製品のランタイム」ではなく「測定器具」として正しい位置にいる。ここに追加投資する意味は薄い(残課題はツールではなく測定→昇格の運用 = issue #51)。

### D が根本解決である理由

現在の構造的弱点は「**絵と領域が別物だからズレる・測る手間が要る・draft が残る**」こと。

- 現行: 絵(JPEG)と領域(JSON)が別アーティファクト → 事後測定が必須 → draft 66件 / ズレリスク / `measuredOn`+hash で絵の差替えを検知する仕組みまで必要
- ベクター原画: 各部位が SVG の名前付きパスとして描かれる → **パスがそのまま領域**。測定工程が消え、座標の draft/measured 区別も不要になり、「絵と領域がズレる」は構造的に不可能になる

商用化のために絵はどうせ差し替える必要がある(PROVENANCE.md: AI生成・権利未確定・内臓図に疑義)。**差し替え時にベクター/レイヤー原画を要求仕様に入れれば、測定パイプラインごと問題が消える**。ラスタを引き続き使うなら現行の計測パイプラインで十分。

## 現行実装で本当に正しい部分(維持すべき)

- **core/ui 分離**: `src/core/` は React/DOM 禁止の純TS。hit-test・投影・ラベル配置が Vitest+Playwright で検証可能。この分離は移植先(ネイティブ/3D/ベクター)が変わっても生きる
- **座標の正本が JSON**: diff・レビュー・ゲート検証が効く
- **画像 hash 連動**: `measuredOn` + sha256 で「絵が変わったのに座標が古い」を検出
- **draft/measured の provenance**: 精度が分かる状態で出荷できる

## 推奨の着地点

1. **ランタイムは据え置き**(現行で本質的。外部ツールに置き換える必要なし)
2. **絵の差し替えと同時にベクター原画を要求**(レイヤー=部位の SVG/AI/EPS 納品)。これが測定工程・draft・ズレ・ハッシュ管理を消す唯一の根治策
3. 差し替えまでの間は現行パイプライン(VIA/自前calibrator → import → validate)を draft 昇格に回す(issue #51 の運用開始)
4. **内臓の右側望だけは反転をやめる判断材料として** S-1 を獣医レビュー(issue #49/SBI-5)に添える。応急処置としては「内臓の右側望を非表示にして未登録メッセージを出す」方が誤った絵を見せるより本質的
