## 読み方と測り方

- 「デザイン」の値は、`doc/design/project/*.dc.html` と共有 CSS（`doc/design/assets/9604617f5b45a642151653a277d5e662.css`）の記述をそのまま引いた。画像（`doc/design/preview/*.png`）は目視。**デザインに書いていない値は作っていない。**
- 「実装」の値は、web の書き出し（`pnpm build` の `dist`）を Playwright（Chromium、ja-JP、deviceScaleFactor 2）で開き、要素の矩形と computed style を読んだ物。画像は DPR 2 なので **画像の px ÷ 2 = CSS px**（矩形の値と同じ）。
- 画面の大きさは 390×844。b159 の最後の列だけ 320×760（デザインの `.ph.n` が幅 320・高さ 760）で、**文字 200%** は `e2e/tools/text-scale.ts` と同じ処理（文字と行高を 2 倍）を当てた。
- **デザインの枠は 360×760**（`.ph`）。390px の実装と横幅が違うので、左右の余白の ±2px 程度は差と見なさない。
- デザインの 3 枚（b159・b56・b173）のヘッダーとタブ名は「描いた当時」の物（`Main.dc.html` の変更記録: 「今の実装は新しい 2 枚に描いてある」）。ヘッダー・タブの差は、その前提で「受け入れ候補」にした。
- 馬の図はデザインでは「原画」の枠（絵を描いていない）。絵そのものの差は比べない。
- 実装の web では react-native-web の都合で、`hitSlop` は効かない（#309 の訂正と同じ）。ここで言う高さは見た目の高さ。
- 測れない・画面に出せない物は **（未確認）**。
- **差の札**: 「直す」= 使い方が変わる差（見える・見えない、押せる大きさ、読む順）。「受け入れ候補」= 見た目だけの差（理由を 1 行）。「修正保留（デザイン確認待ち）」= b173 の差（上の理由）。
- issue 番号（GitHub で確認、2026-11-14）: **#158** は LINE の依頼の PBI「拡大・部位選択中に見える『戻る』導線を追加」、**#159** はその下の SBI「designer: 「1つ戻る」導線の配置・表示名・既存チップ廃止の確認」で、ボード `b159` は #159 のデザイン。この記録は b159 の差を **#159** と書き、親は #158 とする（どちらも closed）。
