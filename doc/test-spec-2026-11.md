## 3つの目

- **仕様の目（S）**: README・AGENTS.md・issue の完了条件に書いてある動きが、その通りに出るか
- **意地悪な試験者の目（T）**: 壊れた入力・直接の URL・連打・保存データの破損・小さな画面と文字拡大で、落ちたり行き止まりになったりしないか
- **利用者の話の目（U）**: 学ぶ人が実際にやりそうな一続きの操作が、途中で迷わず最後まで行けるか

### 不合格の行

- **T07**: 320×568・文字200%（e2e の仕掛けで字の大きさを2倍にする）・日本語で、検索欄の右端が 331px になり、画面（320px）から 11px はみ出す。**main（0fa39e2）でも同じ**なので、開いている PR が持ち込んだ物ではない。main では「まだ」のボタンなどが無く同じ試験はそのまま回らないので、同じ仕掛け（文字2倍・320×568・ja-JP）で /catalog を開き、検索欄だけを測った（使い捨ての試験。右端は `{"right":331,"font":"28px"}`）。検索欄が字の大きさに応じた最小幅を持つため縮まないと見ている（未確認）。新しい不具合として、起票の提案をクラウド作業の記録に書いた。ほかの確かめ（名前が省略されない、絞り込みのボタン・「まだ」・「図」がはみ出さない）は、1つで止めずに全部の合否を出す形にしてあり、どれも合格した
- 画像は合否を確かめる前に撮っているので、T07 の画像にはその時の画面が写っている

### 同じ画面になる行

次の2組は、画面そのものが同じなので画像も同じ中身になる（ファイルは行ごとに1枚ずつある）。

- S01 と T08: `/?part=bogus` は無い部位を無視して、最初の解剖画面を出す
- T02 と T10: 書き出していない URL は、どちらも同じ静的な 404 ページになる

S07 と S13 は同じ画面なので、S13 は一覧の部分だけを撮った。S16 と U04 は、U04 で咬筋の行までスクロールしてから撮った。
