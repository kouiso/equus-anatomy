# #175 独立した原画参照の測定（2026-10-20）

## 結論

独立した参照が1件も無い。そのため IoU と境界距離はまだ測れていない。
受け入れ基準の1つ目は未達のまま残す。

- 対象は 119 部位（左側望 81・正面 28・後面 10）。右側望は左側望の反転なので同じ値になる。
- 独立参照で測定できた部位は 0/119。合格 0、不合格 0、未測定 119。
- 全対象の選択到達性は 200/200 件で確かめた（右側望の 81 件を含む）。

足りないのは部位ごとの参照の領域だけ。
候補座標を見ていない人（持ち主か獣医）が原画の上に描いたものが要る。

## 測定の道具

`pnpm measure:independent` で動く（`scripts/measure-independent-mask.ts`）。

- 参照は `doc/reference-mask/*.json` に置く。当たり領域（`src/core/data/regions/*.json`）とは別の置き場にした。
- 参照ごとに原画のファイル名と SHA-256、向き、プレート、寸法を持たせる。
- 今の原画と SHA が違う参照は stale にして測らない。
- 作者が候補座標を見たと申告した参照（`blindToCandidates: false`）は数字だけ出す。合否には数えない。
- 参照が無い部位は unmeasured のまま。数字を作らない。
- regions の `source`（measured / draft）は読むだけで書き換えない。

IoU は画素の中心で塗った領域どうしで出す。
境界距離は向きごとに 95% 点を px で出す。2つのうち大きい方を使う。
向きは「参照の境界から候補の境界まで」と「候補の境界から参照の境界まで」の2つ。
参照の原画ファイル名が当たり領域の原画と違う時も stale にする。
同じ部位の参照が2枚あれば止める。どの対象にも当たらない id は警告する。

### 参照ファイルの形

```json
{
  "view": "left",
  "plate": "skin",
  "image": "skin_left.jpg",
  "imageSha256": "sha256:4ef4b8cafad90c077792a7a50177626bf9cd91b7ebda516aa905e34c57f52294",
  "size": { "w": 1600, "h": 1200 },
  "annotator": "描いた人",
  "blindToCandidates": true,
  "createdAt": "2026-10-20",
  "method": "描き方",
  "parts": [{ "id": "skin-hoof", "polygons": [[[x, y], [x, y], [x, y]]] }]
}
```

蹄のように離れた塊は `polygons` に複数並べる。座標は原画の実寸 px。

## 実際の測定結果

`src/core/data/regions/*.json` は commit `579be6af` 時点のものを使った。
全行は `measure-result.json` にある。

| 向き | 測定 | 合格 | 不合格 | 未測定 | 当たり領域の source |
|---|---|---|---|---|---|
| 左側望 | 0/81 | 0 | 0 | 81 | measured 6・draft 75 |
| 正面 | 0/28 | 0 | 0 | 28 | measured 3・draft 25 |
| 後面 | 0/10 | 0 | 0 | 10 | measured 2・draft 8 |

使い捨ての参照2枚を使い道具が実画像で動くことを確かめた（コミットしていない）。

- 当たり領域をそのまま写した参照: IoU 1.000、境界 0.0px。作者が候補を見たので not-independent になり合否に数えなかった。
- SHA を壊した参照: stale になり測らなかった。

## 原画だけから参照を作れるか試した結果

候補座標は使っていない。原画の色と輪郭だけで領域を伸ばす方法を4部位で試した。
どれも参照に使える精度にならなかった。

| 試した部位 | 結果 |
|---|---|
| 蹄（皮膚・左側望） | 暗い脚へ漏れた。1か所は種が背景に落ちて取れなかった |
| 肩甲骨（骨格） | 陰影で切れて一部しか取れなかった |
| 骨盤（骨格） | 輪郭は取れたが仙骨の棘まで入った |
| 尾（皮膚） | 黒い背景へ漏れて画面全体になった |

画像は `image-only-segmentation-trial.png` と `image-only-segmentation-hoof.png`。

皮膚の区分（き甲・背・腰など）は絵の上に境目が描かれていない。
筋や骨の境目をどこで区切るかも解剖の知識で決まる。
しきい値や種を部位ごとに手で合わせると手描きの参照と同じになる。
3px の精度を確かめる参照は人が原画の上に描くしかない。

## 拡大・移動・反転の後の到達性

`src/core/data/reachability.test.ts` で確かめた。
画面の当たり判定と同じ順で core の関数を通している。
先に点を拾う。外れたら部位の多角形で拾う。
実物はこの間にラベルの段がある。試験ではこの段を通していない。
輪郭の内側でも別の部位のラベルが乗った所を押すとそのラベルの部位が選ばれうる。
場所を選ばず全部位を並べた状態で見た。実物より点が密なので厳しめになる。

図の上に重ねたボタン（部位一覧・1つ戻る・ズーム・詳しく読む・表示条件）の上は押せない場所として扱った。
ボタンの矩形は配布済みの main（`10ef26a`）で実測した値を使った。
値は日本語表示で部位を選んだ状態のもの。英語表示ではボタンが広くなる。
点の当たり半径は core へ移した。画面と試験が同じ値を読む。
画面がラベルを避けるための矩形（`canvasOverlayRects`）も core へ移した。試験ではそれより狭い実測のボタンの矩形を使う。
実測の手順は `e2e/tools/overlay-measure.spec.ts`、値は `overlay-measure.json` にある。

- 対象は 4 向きの配置済み部位 200 件。右側望は左側望を反転したデータで回した。
- 図の箱は実測のスマホ縦（390x481）とデスクトップ（580x837）。倍率は 1・2・4・8 倍。
- 200 件すべてに点か輪郭の内側を押して選べる倍率があった（両方の画面。ラベルの段は除く）。
- 点が押せる時に押すと全件その部位が選ばれた。
- 2 倍と 4 倍で寄った後に上下左右へ動かした。押せる点は全件その部位を指した。
- 点が押せる倍率がある部位には指が 6px ずれても選べる倍率があった。
- 右側望の点は全件が左側望の点の左右反転だった。

点そのものが押せない組み合わせが 5 件あった（部位 × 倍率 × 画面の 1600 通り中）。
輪郭の内側を押すか倍率を変えれば選べる。

| 部位 | 画面 | 倍率 | 理由 |
|---|---|---|---|
| 鼻先（左側望・右側望） | 両方 | 4 倍 | 画面の外へ出る |
| 中足骨（右側望） | スマホ縦 | 2 倍 | 左下のボタンの下に入る |

鼻先は画面の中心を馬体の上に保つ制限（#65）で中心が体側へ押し戻される。
この一覧は試験の既知一覧に固定した。増減すれば試験が落ちる。
直すかどうかは別に決める。

web の実画面での確認は #176 の証跡（`doc/evidence/176/`）にある。
