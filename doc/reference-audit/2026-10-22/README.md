692は左右や集合骨を展開した構造の総個数ではない。重複表記11組も、独自の`catalog_id`を持つ別行として保持する。IDは調査担当による安定IDで、ベンダー内部IDではない。Android実体・APKは未取得であり、desktop一覧とmobile収録範囲の一致は未確認。購入確認を実体検証の代わりにしない。

87項目のうち、棘上筋・棘下筋・腸腰筋・鎖骨下筋（馬）・盲腸・膀胱の6項目には図上の領域がない。名称の既存登録は保持し、位置や境界は推測で補わない。候補なし31項目のID・名称と、一括対応12組の参照行IDは生成レポートに列挙している。

公式一覧の出典は各行の`source_url`、[Biospheraの製品ページ](https://biosphera3d.com/product/3d-horse-anatomy-software/)。今回の実装は受領台帳の整合検査であり、公開一覧の独立再取得や医学的な再認定は行っていない。

## 編集するファイルと審査方法

[reviews.json](reviews.json)に全692行の未審査レコードがある。原本の初期候補・`synonyms`は仮説として保持し、検索別名へ自動追加しない。人による判断は`nameReview`へ記録する。

| `decision` | 意味 |
| --- | --- |
| `unreviewed` | 未審査。承認ID・根拠・確認者を持たない |
| `synonym` | 根拠で確認した同一構造の名称対応 |
| `equus_contains_reference` | Equus項目が参照構造を包含する |
| `equus_is_part_of_reference` | Equus項目が参照構造の一部 |
| `related` | 関連のみで同一・包含とは認定しない |
| `no_correspondence_after_review` | 根拠を審査した結果、対応未確認。欠落実装を自動指示する値ではない |

名称・包含関係の判断には現行Equus ID、確認者・日付、`terminology`と`independent_anatomy`の根拠IDが必要。根拠には資料の版を含む`source`、具体的なページ・節等の`locator`、対象の`catalogIds`を記録する。用語辞典だけで位置を認定しない。

`spatialReview`の`position` / `laterality` / `depth` / `adjacency` / `projection2d`を独立して審査する。確認済みへの変更には、同一構造の名称対応、対象Equus ID・向き・深さの`targets`、確認者・日付、参照アプリの版・表示箇所と独立解剖資料の根拠が必要。投影には対象の向き・層・深さ・画像SHA-256を持つ`equus_2d`根拠も必要。根拠は対象の参照行へ紐付ける。

「確認済み」は記録された対象と範囲のレビューを意味する。別の向き・深さへ一般化しない。この監査は記録形式と参照関係の整合検査であり、根拠資料の正しさ・画像の権利・医学的な正確性を自動認定しない。左右の全個体展開やmobile同等性、全投影の完成判定も未実装・未確認。現在、実際の根拠は0件で、確認済みにした行はない。

次に必要なのは、正式名と同義語・包含関係の独立資料、参照アプリの対象版で各構造の左右・深さ・隣接を示す表示、そして利用可能なEquus図版上の向きごとの測定・レビュー。未確認の内容や座標を推測で追加しない。クイズは追加せず、既存保存データも変更しない。

## 監査の実行

```bash
pnpm audit:coverage                 # 読み取りのみ。問題があれば終了コード1
pnpm audit:coverage --write-report  # 同じ監査結果をaudit-report.jsonへ生成
pnpm test scripts/reference-audit/audit.test.ts
```

[生成レポート](audit-report.json)は行ごとの初期候補、名称審査、5種類の位置審査、次に必要な根拠を含む。612行を「不足確定」に置き換えない。原本3件のバイト長・SHA-256、692行のID・順序・集計・参照先、全レビュー行、現行87項目との差分を検査する。通常の`pnpm test`でも受領台帳全体の監査が走る。

[geometry-baseline.json](geometry-baseline.json)は監査開始時の4方向の座標・深さ・図版情報の指紋。座標を変更すると監査は失敗し、位置レビューの適用範囲を再確認するよう求める。この一致自体は解剖学的な正確性を示さない。基準更新時も原台帳は書き換えず、変更根拠と再レビュー範囲を記録する。

アプリ実装・図版・座標・保存処理への変更はない。先行する部位名可読性修正と[画像証跡](../../review/2026-10-22-catalog-readability/README.md)、[Draft PR #209](https://github.com/kouiso/equus-anatomy/pull/209)を保持する。今回の検証結果は[validation.md](validation.md)へ記録する。
