# テスト仕様書 — EQUUS 馬体解剖 (Android エミュレータ版)

*2026-09-21 策定。Pixel 6 Pro エミュレータ (API 34) + Expo Go での手動・探索テストの観点表と再現手順。*
*既存 `doc/test-spec.md` は Web(Playwright)版の記録。こちらは Android 実行環境固有の観点を足したもの。*

## 環境

| | |
|---|---|
| 実行環境 | Android Emulator `devin_ps2` (Pixel 6 Pro, API 34, 1440×3120, density 560) |
| アプリ実行 | Expo Go 57.0.9 → Metro (`pnpm start`) に `adb reverse tcp:8081 tcp:8081` で接続 |
| 駆動 | `adb shell input tap/swipe/text` + `adb exec-out screencap` |
| 座標系 | adb tap はデバイス px (1440×3120)。取得スクショを別ツールで見るときは縮尺に注意 |
| 永続データ | AsyncStorage `equus.saved.v1` / `equus.mastery.v1`。リセットはアプリのデータ消去 or `pm clear host.exp.exponent`(Expo Go 全体が消えるので注意) |
| 録画 | `adb shell screenrecord /sdcard/x.mp4` (最長3分) → `adb pull` |

## 観点マトリクス

### T1. 表示条件(向き4 × 層4 × 深さ2)

| # | 操作 | 合格条件 |
|---|---|---|
| 1 | 16組み合わせ全て適用 | 図が描画されるか「この層の図はまだありません」「未配置」等の明示メッセージ。真っ暗・クラッシュは FAIL |
| 2 | 筋肉選択時 | 深さチップ(表層筋/深層筋)が出る。深層筋は図未登録なら disabled + 「図が未登録の深さは選択できません」 |
| 3 | 右側望 | パネルに「左側望の図を左右反転して表示しています。」 |
| 4 | 図のない層(内臓 front/rear 等) | 空 state の文言が出る。壊れた描画でない |

### T2. 部位選択(当たり判定)

| # | 操作 | 合格条件 |
|---|---|---|
| 1 | 初期状態 | 「大まかな場所を選んでください」(area モード) |
| 2 | 場所マーカータップ | 場所選択→部位マーカー表示、「場所を選び直す」が出る |
| 3 | 部位マーカー/ラベル/ポリゴンをタップ | パネルに部位名+summary+「詳しく読む」 |
| 4 | 馬体外の背景タップ | 選択が外れる or 変わらない(意図の確認) |
| 5 | 重なり領域(耳介×頭部) | 小さい側のマーカーを狙って耳介が選ばれる |
| 6 | draft(破線)領域 | 描画が破線で区別される |
| 7 | 「部位一覧」→ 位置未登録部位 | 「この部位は現在の図では位置が未登録です」が出る |
| 8 | 「選択を解除」「場所を選び直す」 | それぞれ期待状態へ戻る |

### T3. ズーム/パン

| # | 操作 | 合格条件 |
|---|---|---|
| 1 | 拡大/縮小/全体に戻る | viewBox が変わり、リセットで初期化 |
| 2 | ドラッグでパン | 図が追従 |
| 3 | ズーム後にマーカータップ | 正しい部位が選ばれる(座標変換の正しさ) |
| 4 | ピンチ | adb では2点タップ不可 → **実機か Maestro で要検証** |

### T4. 詳細・オーバーレイ

| # | 操作 | 合格条件 |
|---|---|---|
| 1 | 「詳しく読む」 | overlay が開き部位名/和名/学名/はたらき/閉じる |
| 2 | Android back | overlay が閉じて選択が維持される |
| 3 | 「詳しく読む」連打 | overlay が1枚だけ・落ちない |
| 4 | overlay 内の保存/覚えた | トグル動作。一覧へ反映 |

### T5. 図鑑

| # | 操作 | 合格条件 |
|---|---|---|
| 1 | 件数表示 | 「52 部位」「覚えた N / 52」 |
| 2 | 検索 | 「肝臓」→1件。ひらがな「かんぞう」も同じ結果(読み検索)。無い語→0件+空表示。長文→落ちない。「消去」→52件復帰 |
| 3 | 絞り込み | 層/場所/向きチップで件数減少。「すべて解除」で復帰 |
| 4 | スクロール最下部 | 崩れなし・下端が見切れない |
| 5 | 行タップ → 詳細 → 戻る | 検索語・絞り込み・スクロール位置が保持される(catalogUiState) |
| 6 | 行の「図」ピル / 詳細の「解剖図で位置を見る」 | 解剖タブへ部位選択状態で遷移(`/?part=<id>`) |

### T6. 保存・覚えた・永続化

| # | 操作 | 合格条件 |
|---|---|---|
| 1 | 詳細で「保存」 | 保存タブに行が出る |
| 2 | 「保存解除」 | undo バー「取り消す」→ 復元 |
| 3 | `am force-stop` → 再起動 | 保存/覚えたが残る(AsyncStorage) |
| 4 | 覚えた→図鑑 | 「覚えた N/52」増加。行に learned 表示 |

### T7. モンキー/異常系

| # | 操作 | 合格条件 |
|---|---|---|
| 1 | ランダム tap/swipe 100+ | クラッシュ・真っ白・操作不能にならない |
| 2 | back 連打 | 壊れない・意図しない終了でない |
| 3 | ホーム→復帰 | 状態保持 |
| 4 | `adb logcat ReactNativeJS` | 赤いエラー(Error/Warning の頻出)がないこと |

### T8. コンテンツ監査(今回追加の観点)

| # | 確認 | 合格条件 |
|---|---|---|
| 1 | 52部位の説明文 | 怪我/疾患/症例/役割が読み取れるか(ユーザーフィードバック基準) |
| 2 | 未配置部位の扱い | 「未配置」が壊れた表示でなく意図的であると読めるか |
| 3 | 右側望・内臓 | 解剖学的に誤った反転絵を出していないか(要獣医判断) |
| 4 | 表示条件の操作数 | 変更に要するタップ数・遷移数がペルソナ(初学者/実務家)に許容範囲か |

### T9. セーフエリア/デバイス差の自動検知(ユーザーより要求)

目的: Pixel 系で左上の時計とアプリ文字が被るような、デバイス依存の重なりを機械的に検知する。

| # | 手段 | 内容 |
|---|---|---|
| 1 | Maestro デバイスマトリクス | `maestro-smoke.yml` の emulator profile を複数化(pixel_6, カットアウト機, 小画面, タブレット)。各機で同じ画面を takeScreenshot し成果物として保存 |
| 2 | スクリーンショット領域チェック | ヘッダ/モーダル最上段のピクセル帯がステータスバー領域と重なっていないか、スクリーンショットの色解析 or UI 要素座標 vs `insets.top` で検査 |
| 3 | 静的チェック | 全画面の先頭コンテナが `useSafeAreaInsets`/`SafeAreaView`/`paddingTop>=insets.top` を使っているか lint or 単体テストで網羅(overlay.tsx は現状未適用) |
| 4 | edge-to-edge 確認 | `app.json` に `android.edgeToEdgeEnabled` 未設定 → SDK 53+ で既定 ON。実機/dev build で「モーダルヘッダが時計と被らない」ことを検証項目に追加 |

## 既知の制約

- **ピンチ(2点)は adb 不可**。実機 or Maestro(Firebase Test Lab)で別途
- **Expo Go は dev 用**: dev 歯車の表示・起動の遅さは本番と別物。最終品質判断は dev build/FAD 配布で
- エミュレータの GPU は SwiftShader → 実機より描画が遅いことがある。体感性能の判定は実機で
